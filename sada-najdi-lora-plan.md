## Step 1 — Data prep (the step that decides everything)

- Filter SADA train split: dialect ∈ {Najdi, Hijazi}; clean ProcessedText (drop music/unclear
  markers, dedupe, 20–300 chars); keep a quality sample (~50–100k utterances candidate pool).
- Build ~15–20k training pairs, three kinds (ALLaM-paper recipe + self-instruct):
  1. **Reverse-instruction** (~60%): local qwen writes a natural user question whose answer is
     the AUTHENTIC SADA utterance — synthetic inputs, real dialect outputs.
  2. **MSA→dialect rewrites** (~15%): qwen translates Najdi→MSA (the reliable direction), we
     train the reverse (MSA in → authentic Najdi out).
  3. **Preservation mix** (~25%): English + Fusha + Egyptian pairs generated by base qwen
     answering fresh questions (self-distillation = "do not change this behavior") — the
     guard against over-casualization and English/SQL-style degradation.
- Train WITHOUT the dialect cards in the prompt (the model should become natively Najdi;
  cards stay in production as belt-and-suspenders). Qwen chat template; held-out val slice.
- Pair generation runs on the GPU via Ollama for ~half a day (batched).
- **Checkpoint: owner reviews a 50-pair sample by eye before training.**

## Step 2 — Training (night 1)

- 30-min smoke run first (200 steps — validates VRAM/stack before burning a night).
- Full run: QLoRA r=32, all linear layers, batch 2 × grad-accum 4, seq 1024, 2–3 epochs over
  ~15–20k pairs ≈ 6–10 h on the 5090 (~22 GB). Voice stack DOWN during the run.

## Step 3 — Morning A/B (day 2)

- Add `--model` arg to `eval/dialect_ab.py` (few lines).
- Package adapter for Ollama: convert_lora_to_gguf → `ADAPTER` Modelfile over the existing
  qwen3.5:27b GGUF → tag `qwen3.5-saudi:testN`. (If runtime-adapter is flaky: merge to bf16 +
  quantize q4_K_M — robust fallback, +2–3 h CPU.)
- Run the A/B: base vs adapter, same 60 fixed questions; linter columns + would-fix counts +
  **owner's ear on both reports**. Also full `eval/test_routing.py` (prompt layer — must stay
  green) and an English-quality eyeball on the same questions.

## Step 4 — Iterate (expect 2–3 runs total)

Standard first-run diagnoses → fixes: effect too weak (more epochs / higher rank), Fusha or
English got casual (raise preservation mix), broadcast-news flavor bleeding in (tighter SADA
filtering), leaks unchanged (check pair quality, not hparams). Each cycle = daytime adjust +
overnight train + morning A/B.

## Step 5 — Ship (half day)

- Final adapter → `qwen3.5-saudi` tag; server model selection via one constant/env var
  (default stays plain qwen — flip only after live test). Live voice session: owner's ear +
  linter on the fresh rows. CLAUDE.md: model note + SADA license entry. Owner commits.
